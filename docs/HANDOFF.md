## Запрос владельца от 23.10.2026 (из облачного чата)

**Запрос.** «Хочу такой же функционал, как описано здесь: https://www.docjuris.com/solution/contract-review-redlining.
Также хочу, чтобы таблицы из Word переносились целиком: таблица пропала при сравнении» (на снимке экрана — перечень услуг
из п. 1.2 договора с ИП Ганжа, ячейки шли столбиком).

**Сделано (коммит 12cf73e в `feature/unified-version`).** Таблицы собираются целиком: `docx_reader` запоминает для абзаца
в ячейке `Paragraph.table = (таблица, строка, столбец, ширина gridSpan)`; `unified.build_unified` отдаёт `table` и не
выбрасывает пустые ячейки; значение, удалённое без отметки, ставится в свою ячейку (`_removed_cell`); `review.js`
(`blocks`, `tableRow`) рисует таблицу целиком, заметки ко всем её правкам — справа. Тест: `tests/test_unified.py`
(падает без исправления). Проверено в браузере на договоре с ИП Ганжа.

**Сравнение с DocJuris (ответ владельцу).**

| Функция DocJuris | У нас | Не хватает |
|---|---|---|
| Правки в Word с настоящим рецензированием (принять/отклонить) | Word с примечаниями | Наши ответные правки как отслеживаемые изменения: вернуть нашу редакцию или вставить уступку из плейбука |
| Guided Review: текст и рекомендация рядом, «применить / пропустить» до сборки файла | Список правок и единая версия | Кнопки «применить / пропустить» и сборка Word по выбору |
| Сводный отчёт: итог, ключевые условия, риск по сторонам, тепловая карта, варианты торга, чего нет в договоре | Счётчики, решения, предупреждения | Ключевые условия, тепловая карта по темам, отсутствующие обязательные пункты, путь «позиция → уступка → красная линия» |
| Связь правки с позицией плейбука и автором | Есть | — |
| Word и PDF, в том числе защищённые | Только Word | PDF |
| Плейбук: сохранённый, разовый, указания текстом, без плейбука | Сохранённый, без плейбука | Разовый плейбук и указания текстом |
| Проверка перед подписанием (ссылки, определения, нумерация) | Нет | В планах |
| Надстройка Word, приём по почте, уведомления | Нет | Позже |

Ограничение остаётся: ответные формулировки — только из плейбука или прошлых договоров юриста, модель их не сочиняет;
каждый выходной файл — черновик.

**Предложенный порядок (ждём подтверждения владельца):**
1. Пошаговый просмотр + ответные правки в Word с рецензированием (автор «Правки (черновик)»).
2. Сводный отчёт: ключевые условия, тепловая карта, отсутствующие пункты, путь торга.
3. PDF и разовые указания вместо плейбука.
4. Проверка перед подписанием.

Владелец работает в двух чатах (облачный и VS Code) с одной веткой — перед работой проверять `git log` и не править
одно и то же параллельно.
